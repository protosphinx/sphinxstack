Worked case: add regions without creating global correctness failures

Trigger: A subscription service is adding two regional origins behind a global edge, but authenticated pages, country pricing, sessions, replicated data, cache variants, attack traffic, cold-cache failover, residency rules, and origin recovery have not been reconciled.

Can the CDN cache every HTML page by URL?
No. Authentication, country, currency, language, experiments, and authorization can change the response and its safe cacheability.
Should traffic fail over immediately when one health check fails?
Use independent evidence, bounded propagation, and staged steering so a false signal or cold cache does not overload the survivor.
Can sessions follow users to any region?
Only if identity, data consistency, residency, revocation, and failure behavior support that promise.
What proves origin recovery?
A clean restore, data and session checks, safe cache treatment, canary traffic, and gradual return under measured capacity.

Failure rehearsal

A canary cache test serves account HTML across sessions because the key omits identity state. Private routes bypass edge storage immediately, affected cache scope is purged, and evidence is preserved. A later origin-loss exercise stages traffic because the surviving region cannot absorb cold-cache demand.

Questions people actually ask

Can personalized pages be cached?

Only with proven isolation, variants, authorization, and invalidation; bypass is often safer.

What should health checks measure?

Representative ability to serve the journey, with independent routing and dependency evidence.

How is failover capacity calculated?

Include attack load, cold caches, retries, dependencies, and staged traffic concentration.

Can data residency be handled by DNS?

No. Routing, storage, replication, processing, logs, and recovery all need enforceable rules.

When does a recovered origin receive full traffic?

After clean restore, reconciliation, canary outcomes, and measured capacity pass.
