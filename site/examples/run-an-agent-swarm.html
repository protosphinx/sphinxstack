Worked case: six agents on one Rust repository overnight

Trigger: Three Codex agents and three Claude Code agents need to work one repository overnight without colliding.

I want three Codex workers on gpt-5.6 Sol at maximum reasoning and three Claude Code workers on Opus 5 at xhigh against this repo tonight. Can you set it up?
First I read every applicable AGENTS.md and the README, map the architecture, and verify that exact roster. Then: how long is a cold build, how much disk does one build take, and is there a queue of items already written down?
Cold build is about nine minutes and eats 12 GB. There is no queue, just a list of things I want fixed.
Then six independent builds would need 72 GB and thrash the machine. We use one shared cached build path, one build at a time, and I turn your list into queue items with a statement of done before any agent starts.
Can the agents just pick their own work?
No. Each agent claims one item and works only the files that item names. Anything they discover becomes a new item, not an unplanned edit.
What happens when one of them dies at 3am?
The supervision cycle runs every four minutes. A claim with no commit for three cycles is released back to open with a note, and the idle agent gets fresh instructions.

The queue and the build budget come before the agents.

Failure rehearsal

At 02:15 two agents both edit the scheduler module and the second branch conflicts. Review catches it, the second item returns to open with the first change linked as context, and the queue owner resplits the two items so they stop overlapping. At 04:40 free disk drops under the threshold, so the cycle stops handing out work, prunes finished worktrees, recovers 90 GB, and resumes. Nothing merges while either condition is open.

Questions people actually ask

How many agents should I run?

As many as the build path and disk can carry, which is usually far fewer than the number you can afford to start. Run one full cycle, then add agents only if it stayed green.

Do I need this exact tool and model stack?

No. The method needs a session host, shared queue, isolated checkouts, serialized build runner, and supervisor. If you requested specific tools or models, the orchestrator must verify them and ask before substituting.

What stops agents from doing random work?

The queue. One item per owner, and anything discovered becomes a new item. An agent that cannot claim an item is idle, which the supervision cycle reports rather than hides.

How do I know when to stop a review round?

Track defects found against effort spent. When that ratio flattens across rounds you have hit saturation, so switch to a different kind of pass or stop.

Can the swarm merge its own work?

No. A reviewer who did not write the change checks it against the statement of done, and a person merges. That is the control that makes an unattended run safe to leave running.
