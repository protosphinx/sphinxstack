Worked case: replace a live interface without losing learned workflows

Trigger: A global project platform must replace navigation, record pages, bulk actions, keyboard shortcuts, filters, saved views, and its component system while enterprise users rely on bookmarks, screen readers, training guides, support scripts, integrations, and long-running sessions and cannot lose state during coexistence or rollback.

Can we measure success by new-interface adoption?
No. Measure supported outcomes, errors, accessibility, support, and harm alongside adoption.
Should users switch versions on every login?
No. Keep assignment stable so behavior and evidence remain interpretable.
Can old bookmarks go to the home page?
Map each supported route to its equivalent outcome or explicit retirement.
What makes rollback safe?
Shared authoritative state, compatible presentation, preserved links and views, and a rehearsed recovery path.

Learned behavior is part of compatibility.

Failure rehearsal

An enterprise user's saved filter opens in the new interface but changes scope silently. The cohort returns to the verified presentation, authoritative records remain unchanged, the mapping and scope indicator are repaired, and saved-view parity is retested before expansion.

Questions people actually ask

Should every accidental legacy behavior remain?

No. Classify relied-on, safe, harmful, and unsupported behavior explicitly.

Can a tour replace compatibility?

No. Guidance cannot repair missing outcomes, links, state, or access.

Who should enter a canary?

Known users and cohorts whose risk, support, and exit path are controlled.

Can rollback move new records back?

Keep authoritative state stable and roll back only compatible layers.

When can the old interface retire?

After usage, obligations, accessibility, support, integrations, and recovery gates pass.
