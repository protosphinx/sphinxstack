Worked case: consolidate tenants without crossing boundaries

Trigger: A growing project-management SaaS is consolidating separate customer databases into shared regional storage, but API routes, search, cache keys, exports, background jobs, signed file URLs, support impersonation, and recovery tools derive tenant context differently while enterprise launch is six weeks away.

Can we add a tenant filter to repositories and finish the migration?
No. A filter covers only one boundary. First define isolation invariants across requests, storage, jobs, caches, search, files, exports, support, and recovery.
The tenant ID is already present in every request.
Presence is not trust. Derive tenant context from authenticated membership, bind it to the resource, and deny missing or conflicting context.
Support needs a fast way to enter any tenant.
Use an approved, time-limited, attributable support grant with notice and immutable audit evidence. Do not create a hidden universal bypass.
What blocks the launch?
Any unowned boundary, policy mismatch, cross-tenant test failure, or unrehearsed recovery path blocks it.

Prove the invariant at every path.

Failure rehearsal

Shadow evaluation finds that an export worker accepts the tenant ID from its queue payload and reads a document by global ID. The wave stops, affected exports are disabled, evidence is preserved, and the worker is changed to load trusted job ownership before the shared decision point evaluates access. The full queue and export matrix is repeated before launch.

Questions people actually ask

Can a tenant ID in a signed token be trusted?

Only after the token, issuer, audience, session state, and current membership have been validated for the requested action.

Is a database row filter enough?

No. Search, caches, files, jobs, exports, support tools, and application relationships also need enforced isolation.

How should shared resources work?

Model explicit ownership and collaboration relationships, then authorize each action through the same decision contract.

Can support impersonate a tenant administrator?

Only through a narrow approved workflow with proof, purpose, expiry, notice, attribution, and review.

What should happen when tenant context is missing?

Deny the action, record a safe diagnostic, and repair the caller instead of selecting a default tenant.
