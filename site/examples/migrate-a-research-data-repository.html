Worked case: move governed research collections

Trigger: A multi-institution repository must move genomic data, Indigenous-governed collections, licensed surveys, embargoed theses, software, versions, and DOI landing pages before source shutdown, but checksums are incomplete and the target uses different metadata, identity, access, and preservation models.

Can we copy objects first and fix metadata later?
No. Inventory rights, consent, community authority, versions, relationships, identifiers, and preservation state before access changes.
What if an object has no checksum?
Generate one from the preserved source and record that no earlier fixity baseline exists.
The target cannot represent one consent restriction.
Quarantine access and obtain authority. Never default the collection to open or silently flatten the rule.
What proves migration?
Object fixity, metadata, rights, identifiers, relationships, access journeys, restore, delta capture, and rollback all reconcile.

Failure rehearsal

A DOI resolves, but the landing page exposes restricted geographic metadata. The collection remains quarantined, the mapping is corrected, disclosure tests rerun, and every related version is checked before the route is enabled.

Questions people actually ask

Can identical files be deduplicated?

Only after versions, relationships, retention, rights, citations, and approved disposition are preserved.

Must persistent identifiers stay the same?

Preserve their resolution and citation contract; never silently reuse an identifier for different content.

How are Indigenous data rights handled?

Through the applicable community authority and governance, not a generic open-data default.

Is a byte-count match sufficient?

No. Verify object fixity, metadata, versions, relationships, identifiers, access, and workflows.

When may the source shut down?

After preservation, governance, legal, operational, and rollback owners accept the evidence.
