Worked case: move a global account service to a new domain

Trigger: A global account-based web service must move from an old domain to a new one while preserving DNS, email, certificates, authentication cookies, OAuth and SAML callbacks, passkeys, API clients, mobile deep links, indexed URLs, regional origins, security policies, and millions of saved links without creating an open-redirect or account-takeover path.

Can we redirect the old domain and copy its session cookie?
No. Cookies and identity properties are origin-bound. Map each identity transition and require safe reauthentication or parallel enrollment.
Should we temporarily allow every callback and return URL?
No. Arbitrary callbacks and return URLs create account-takeover and open-redirect paths.
Is one successful DNS check enough?
No. Verify authoritative and recursive resolution, TLS, identity, routes, and behavior from independent regions.
What keeps rollback safe after users write through the new domain?
Use shared authoritative state or state-compatible recovery, then rehearse rollback without losing accepted changes.

Failure rehearsal

A canary region resolves the new domain, but its enterprise login callback still targets the old audience. The wave stops, users remain on the supported old origin, the registration and account-binding tests are corrected, and regional parity is rerun before expansion.

Questions people actually ask

Can an old cookie be copied to the new domain?

No. Design a safe transition that respects browser origin boundaries.

Should the old domain expire after cutover?

No. Keep it controlled, renewed, monitored, and narrowly redirected for the approved compatibility period.

Do passkeys move automatically?

Often not. Treat relying-party changes as an identity migration that may require parallel enrollment.

When can DNS TTLs return to normal?

After regional resolution and application behavior remain stable through the observation window.

What blocks retirement?

Any supported client, identity dependency, material route, or rollback gate without verified disposition.
