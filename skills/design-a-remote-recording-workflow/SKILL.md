# design-a-remote-recording-workflow

Use the call for direction and local files for quality where possible.

## When to use

- Use for podcasts, interviews, voice, panels, remote video, or pickups.
- Verify unfamiliar platforms and never request unnecessary device, account, or remote-control access.

## Procedure

1. Confirm participants, roles, locations, time zones, rights, recording consent, accessibility, privacy, and data handling.
2. Choose platform, local recorder, camera, microphone, monitoring, isolated tracks, file format, and backup for each person.
3. Provide a minimal setup guide and conduct a device, room, framing, network, power, storage, and permission test.
4. Record a slate, reference clap, pronunciation, level, room tone, and backup call.
5. Monitor clipping, noise, echo, focus, sync, network, local record status, storage, and participant comfort.
6. Keep the network mix as reference and preserve independent local files.
7. Define reconnect, crash, power, storage, upload, participant withdrawal, and lost-file procedures.
8. Transfer through an authorized route with progress, resume, checksum, and access expiry.
9. Verify files, metadata, sync, duration, permissions, backups, and deletion commitments.

## Failure plan

- If local recording status is unknown, pause and verify rather than assuming the platform captured it.
- If a participant withdraws within the agreed boundary, quarantine affected media and follow the recorded disposition.

## Done

- A remote recording plan records participants, consent, equipment, local and backup capture, accessibility, transfer, and failure procedures
- Rehearsal and ingest evidence verify audio, video, sync, local files, backups, checksums, access, and participant boundaries
