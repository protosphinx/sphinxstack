# create-a-service-blueprint

## Procedure

1. Define the service outcome, user group, journey boundaries, scenario, and evidence sources.
2. Map user actions, needs, questions, wait, and observable experience over time.
3. Add frontstage people, interfaces, messages, and physical touchpoints.
4. Add backstage actions, decisions, queues, handoffs, systems, data, vendors, and policies.
5. Mark lines of interaction, visibility, responsibility, and dependency.
6. Record evidence, assumptions, time, volume, failure, recovery, and owner at each step.
7. Identify mismatched promises, duplicate work, hidden labor, inaccessible paths, and control gaps.
8. Model one normal and two failure scenarios, including degraded service.
9. Prioritize changes by user harm, feasibility, dependency, and verification.
10. Validate the blueprint with users and delivery staff, then version it.

## Guardrails

- Do not treat workshops as evidence of the user's experience.
- Protect employee and customer details in journey evidence.
- Avoid blaming frontstage staff for backstage constraints.

## Done

- A service blueprint records journey, frontstage, backstage, systems, rules, evidence, and owners
- Failure walkthroughs expose handoff and recovery gaps
- User and delivery-team verification is recorded
