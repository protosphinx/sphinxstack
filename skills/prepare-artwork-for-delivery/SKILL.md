# prepare-artwork-for-delivery

Treat delivery as a production gate. Preserve editable sources while giving the recipient exactly the approved files and specifications.

## Procedure

1. Obtain the current delivery specification directly from the printer, platform, developer, publisher, or client.
2. Inventory approved variants, sizes, languages, states, channels, and source ownership.
3. Check dimensions, bleed, trim, safe area, resolution, color space, profiles, transparency, compression, and file format where applicable.
4. Verify typography, font rights or outlining rules, linked assets, image rights, logos, marks, and required credits.
5. Check copy, data, legal text, accessibility, contrast, reading order, alt-text handoff, and localization.
6. Compare outputs with the approved master and remove stale, hidden, or unintended content.
7. Name and organize files by a documented convention; include a manifest with version, purpose, dimensions, checksum, and source.
8. Export through the actual production path and inspect rendered or proof output at relevant size.
9. Deliver through the approved channel, preserve editable sources separately, and obtain recipient confirmation.

## Failure plan

- Do not substitute guessed production settings for the recipient's current specification.
- Never package unlicensed fonts, images, templates, or confidential working files.
- If export changes appearance, stop and resolve it before delivery.
- Do not overwrite the approved source with flattened delivery output.

## Done

- Every required variant passes technical, content, rights, and accessibility preflight
- Manifest, filenames, versions, and checksums are verified
- Recipient opens the package successfully and acceptance is recorded
