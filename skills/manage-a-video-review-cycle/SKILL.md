# manage-a-video-review-cycle

Review one named version against one named decision.

## When to use

- Use for rough cut, fine cut, picture lock, sound, caption, color, compliance, and final approval.
- Do not collect sensitive footage in an uncontrolled public review link.

## Procedure

1. Define review stage, artifact version, watermark, access, expiration, reviewers, decision owner, scope, and deadline.
2. State what is locked, what can change, and the cost of late structural feedback.
3. Provide a reference player or file with reliable timecode, captions, audio, and target framing.
4. Ask reviewers to classify feedback as error, risk, required change, question, or preference with rationale.
5. Consolidate duplicates and conflicts without erasing dissent.
6. Route fact, participant, rights, privacy, accessibility, legal, brand, editorial, and technical comments to qualified owners.
7. Record each comment's source, timecode, decision, response, owner, target version, and status.
8. Export the next version from a controlled project and verify every accepted change plus regressions.
9. Close the stage with explicit approval, open exceptions, and next-review scope.

## Failure plan

- If reviewers comment on different versions, stop reconciliation and reissue one controlled artifact.
- If late feedback changes facts, rights, safety, or accessibility, reopen the appropriate gate regardless of schedule.

## Done

- A review tracker records version, access, stage, timecoded comments, classifications, decisions, owners, status, and approval
- Change verification proves accepted notes landed in the target export and unresolved exceptions remain visible
