# review-a-design-at-zoom

Test real journeys, not a single enlarged screenshot.

## When to use

- Use for responsive web interfaces, forms, navigation, dialogs, tables, checkout, and content pages.
- Do not disable zoom or require horizontal scrolling for ordinary reading when reflow is expected.

## Procedure

1. Define browser, viewport, device scale, page state, task, and supported accessibility baseline.
2. Test browser zoom through the required range and text-only enlargement where supported.
3. Complete navigation, reading, input, validation, overlays, tables, and recovery at each critical size.
4. Check clipping, overlap, lost content, offscreen focus, fixed headers, scroll traps, control targets, and line length.
5. Test long translations, dynamic errors, user-generated content, landscape, and virtual keyboard behavior.
6. Record exact route, setting, steps, expected result, actual result, and severity.
7. Retest the same journey after changes and check adjacent breakpoints.

## Done

- A zoom review report records configurations, tasks, screenshots, barriers, impact, and ownership
- Retest evidence verifies content and controls reflow, remain visible, and support complete journeys at required zoom
